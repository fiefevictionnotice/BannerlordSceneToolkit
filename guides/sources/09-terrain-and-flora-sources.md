### TERRAIN (#bl-scenes)

- **Scene size math: scene length = nodes x single-node length (m); vertices per node = "Single Node Dimensions".** Max is 16x16 nodes and 1024x1024 vertices per node. gkx's rule of thumb is 1-2 vertices per metre (0.5 m/sample is very detailed). Example: 1 km scene = 10x10 nodes of 100 m, 128 or 256 vertices per node.<br>gkx (TW), npc99., 2020-10-02/04 · confirmed · [gkx, 2020-10-02](https://discord.com/channels/411286129317249035/761302555308720148/761670171684503552)
- **Heightmap pixel count should equal nodes x vertices per node (e.g. 16x16 nodes at 256 = 4096 px); neighbouring nodes share stitching vertices, so 10x10 nodes at 256 needs a 2561x2561 map.** Higher-resolution images are downscaled with no performance cost; lower ones get stretched/interpolated or blocky.<br>npc99., poheniks, Cuce (TW), 2020-10-04/08 · confirmed · [npc99., 2020-10-04](https://discord.com/channels/411286129317249035/761302555308720148/762412378045808681)
- **Import heightmaps as 16-bit single-channel PNG (or raw/tga); 8-bit or JPG gives stepping/jagged precision artifacts.**<br>gkx (TW), Muret (TW), Vertreter, 2020-10-02/08 · confirmed · [gkx, 2020-10-02](https://discord.com/channels/411286129317249035/761302555308720148/761672372856029194)
- **Heightmap import workflow: set node count/size BEFORE generating terrain; then in Terrain mode (Alt+7 / "Select Terrain" button), select all nodes with Ctrl+A and use "Import heightmap".** The scale/offset text shown after export/import vanishes quickly, so note it down. Importing with one node selected fills just one square.
